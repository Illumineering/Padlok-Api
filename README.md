# Padlok API

Stores the addresses Padlok users share, sealed on their device. The server only ever
sees encrypted blobs: the passphrase that opens them travels in the share link's
fragment, which never reaches the server.

[`openapi.yaml`](openapi.yaml) is the contract, edited by hand. The clients are
generated from it.

## Swift client

Add `https://github.com/Illumineering/Padlok-Api` to the app's packages, then:

```swift
import OpenAPIURLSession // https://github.com/apple/swift-openapi-urlsession
import PadlokAPIClient

let client = try Client.padlok(serverURL: Servers.Server1.url(), transport: URLSessionTransport())

let created = try await client.createShare(body: .json(.init(iterations: 1000, salt: salt, sealed: sealed)))
    .created.body.json
try await client.updateShare(identifier: created.identifier, adminToken: created.adminToken, info: info)
try await client.deleteShare(identifier: created.identifier, adminToken: created.adminToken)
```

Build the client with `Client.padlok(…)`: it sends the admin token as a Bearer token,
after your own middlewares have run, so they never see it.

The package only depends on `swift-openapi-runtime`. The client is generated by
`scripts/generate-client` and committed; run it after changing `openapi.yaml`.

## Kotlin client

The Android app generates its own from `openapi.yaml` at a release tag, with the
[OpenAPI Generator Gradle plugin](https://github.com/OpenAPITools/openapi-generator/tree/master/modules/openapi-generator-gradle-plugin):
generator `kotlin`, library `jvm-ktor`, `serializationLibrary=kotlinx_serialization`.
